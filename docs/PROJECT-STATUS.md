# Статус проекта

> Что сделано, что проверено вживую и какие факты не выводятся из кода.
> Общее описание системы — в [`README.md`](../README.md).

Студенческий проект для **кафедры физической культуры РЭУ им. Плеханова**. Цель: заменить
бумажный учёт медсправок студентов живым реестром допусков к физкультуре.

  (`appsettings.Development.json`) — авто-сидер демо-студентов БОЛЬШЕ НЕ ЗАПУСКАЕТСЯ. Если реестр пуст —
  это норма, НЕ возвращай демо. Справочники (9 подразделений, 76 физруков, 2 учебные группы) сохранены.
  Реальные студенты заводятся заново через загрузку фото справок +
  ИИ-распознавание/подтверждение ЛИБО ручным вводом/импортом.
- **ВАЖНО про потерю данных:** работа сессии 2026-06-21 (реальные студенты, распознанные справки) была
  потеряна при выключении компа — в `reu-pg` её НЕ оказалось (append-only аудит обрывается на 2026-06-16,
  колонки `Type` не было → апп не запускался против этой базы после 16-го). Урок: данные durable только если
  апп реально пишет в `reu-pg` (volume `3116f26…`) И есть `pg_dump`-бэкап. Бэкапа на момент инцидента не было.
- **Реестр преподавателя** (`/registry`) теперь показывает колонку **«Тип справки»** (086/у · Бассейн ·
  Освобождение · Иная) рядом с группой здоровья (римские I–V), сроком и статусом. Проверенная справка
  (`VerificationStatus=Verified`) выводится как «Действует/Истекает/Истекла», а не «На проверке».
  Проверено вживую через Playwright (логин teacher) на временной записи, затем запись удалена.
- **БОЕВОЙ ДЕПЛОЙ (2026-06-23): на десктопе `castiel-pc`**, НЕ на ноуте. Публичный адрес
  `https://<ваш-узел>.ts.net` (Tailscale **Funnel = публичный интернет**, за логином).
  - Системный сервис `reu-medspravki.service` (`/etc/systemd/system/`, User=Castiel, autostart, Restart=on-failure),
    WorkingDirectory `/home/Castiel/reu-medspravki-pub`, `ASPNETCORE_URLS=http://0.0.0.0:5080`, env Development.
  - БД: docker `reu-pg` на castiel-pc (порт 5432, restart=unless-stopped). Ollama локально (vision-распознавание).
  - Деплой = rsync публикации ноута → `/home/Castiel/reu-medspravki-pub/` + `pg_dump` ноута → restore в reu-pg castiel-pc.
  - SSH с ноута: алиас `pc-castiel` (User Castiel, Tailscale <tailscale-ip>). passwordless sudo есть.
  - ⚠️ **152-ФЗ риск:** медданные на ПУБЛИЧНОМ funnel за дефолтным паролем `teacher`/`<демо-пароль>` —
    СМЕНИТЬ пароль обязательно; рассмотреть приватный `tailscale serve` (только тайнет) если студентам дать доступ иначе.
- **Дев-инстанс на ноуте** (`castiel-laptop`): отдельный reu-pg + `systemd-run --user reu-medspravki` на localhost:5080 —
  для разработки. Боевой — только castiel-pc. Не путать БД ноута и десктопа.
- **Новое в реестре (2026-06-23):** колонка «Тип справки» (все типы студента через « / », напр. «086/у / Бассейн»);
  статус «**Не допущен**» (валидная справка-недопуск, поле `MedicalCertificate.Admitted=false` — приоритетнее срока);
  «**Заявка отклонена**» (есть отклонённый по качеству скан, справки нет) вместо «Нет справки». Авто-ревью теперь
  отделяет недопуск (создаёт справку Admitted=false) от брака (печать/срок/ФИО → отказ скана). Карточка студента
  показывает «Допуск: Допущен / НЕ допущен».
- **Правка справок преподавателем (2026-06-23):** кнопка «Изменить / поправить» в карточке студента
  (текущая справка + история) → форма `/students/{id}/certificates/{certId}/edit` (`CertificateService.UpdateAsync`,
  аудит «Edit»). Правит даты/тип/допуск/группу здоровья/физгруппу/номер/орг/ограничения; правка = подтверждение
  человеком (→ Verified, статус «Действует/Истекла» пересчитывается по новым датам). Нужна, т.к. 7B-модель
  ошибается на рукописи (даты/группа/номер). У типа «Бассейн» группа здоровья НЕ подставляется (там группы А/Б).
- **АВТО-двухэтапное распознавание (2026-06-23):** в `LocalOllamaRecognitionProvider` после общего прохода
  (стадия 1, вся справка) идёт **стадия 2 — модель САМА перечитывает ключевые поля** (issue_date/number/
  health_group) по каждой странице ОТДЕЛЬНЫМ фокус-запросом и подставляет уточнённое значение. Флаг
  `Recognition:TwoStage` (дефолт true). Дату выдачи берём с самой поздней страницы/ниже по листу (НЕ дата
  лицензии из шапки). Проверено вживую на живой справке: стадия 2 исправила год **2023→2025** (issue_date 22.11.2025),
  номер 01677 — полностью автоматически, без препода. Цена: +~6 модельных вызовов (~5-6 мин фон. авто-ревью).
  **ВАЖНЫЙ вывод:** «зум вниманием» (фокус-запрос по ОДНОМУ полю на полной странице) НАДЁЖНЕЕ пиксельного
  кропа — тесный кроп теряет контекст и даёт мусор (тест: 18.01.2019/05.12.2017), а фокус-запрос стабильно
  дал 22.11.2025. Поэтому авто-стадия 2 — фокус-запросы, БЕЗ кропа.
- **Надёжность распознавания (2026-06-23):** к авто-стадии 2 добавлены (опции в `Recognition`):
  (1) **голосование** по дате выдачи — `VoteCount` (деф. 3) чтений с temp>0, берём большинство;
  (2) **флаг неуверенности** — если голоса по дате разошлись ИЛИ стадии 1↔2 не сошлись по номеру/группе,
  поле помечается, и в `CertificateScan.AiNotes` пишется «⚠ Проверьте (распознано неуверенно): …» (справка
  всё равно создаётся как лучшая догадка, но препод видит, что проверить кнопкой «Изменить»);
  (3) **предобработка** фото (`Preprocess`, деф. true) — нормализация контраста + резкость (ImageMagick),
  без агрессивного дескью/бинаризации (рискованно на фото). Проверено вживую на живой справке: дата 22.11.2025
  уверенно, номер 01677 уверенно, группа здоровья помечена на проверку. Главная мысль: модель учится
  ЧЕСТНО сигналить о неуверенности, а не молча подставлять. Сильнее всего поднимет точность бОльшая
  локальная модель — когда РЭУ даст GPU-сервер (всё равно ТОЛЬКО локально, 152-ФЗ).
- **Ручной зум по полям (fallback):** страница `/students/{id}/scans/{scanId}/zoom` — препод выделяет мышью
  область на скане (canvas), выбирает поле, «Распознать выделенное» → сервер рендерит (pdftoppm) + режет с
  увеличением (magick) + узкий запрос (`IRegionRecognizer`/`RegionRecognizer`). Эндпоинты `?handler=Page&n=N`
  и `?handler=Recognize`. Для случаев, где авто-стадия 2 не справилась; значение копируется в «Изменить».
- Логин преподавателя: `teacher` / `<демо-пароль>` (BootstrapUser, создаётся всегда). Демо-логины
  head/admin/student при `SeedDemoData=false` НЕ создаются.

## Ключевые факты (не выводятся из кода)

- **Два scope.** Действующее официальное ТЗ v1 = РУЧНОЙ вариант (преподаватель вносит справки;
  ПРЯМО исключает загрузку студентами, сканы, OCR — разд. 5.2/31). Заказчик-студент (Даня) хочет
  АМБИЦИОЗНЫЙ v2: личный кабинет студента + загрузка фото + ИИ-распознавание + маршрутизация к
  физруку + влияние на оценки. Это раздел §33 ТЗ «развитие после MVP».
- **Скаффолд `_source/scaffold/ReuMedCertificates/` НЕ компилируется** — Domain/Application пусты,
  но `Program.cs`/`DI` уже заточены под student-portal/OCR (`AppUser`, `ApplicationDbContext`,
  `IStudentPortalService`, `RegisterStudent`, `SeedIdentityAsync` — этих типов нет). Старт = с минуса.
- **Стек (утверждён ТЗ):** ASP.NET Core 8 + Razor Pages + HTMX + Bootstrap 5.3 + PostgreSQL 16
  (pg_trgm) + EF Core 8 + ASP.NET Identity + ClosedXML + Serilog. Clean Architecture. IIS / Windows / ЛВС РЭУ.
- **Главный конфликт:** заказчик видит развёртывание ОФЛАЙН («сетевая папка / флешка на оборудование РЭУ»),
  а студ-загрузка/уведомления/облачный ИИ требуют сети. + скан медсправки = спецкатегория ПДн
  (152-ФЗ ст.10) + врачебная тайна (323-ФЗ ст.13) → US-облака (OpenAI/Gemini/Claude) запрещены.
- **Стратегия (Claude+Codex согласны):** (1) сначала довезти компилируемый v1 (реестр, CRUD,
  импорт/экспорт Excel, AuditLog, computed-статус, сидинг 9 факультетов/13 физруков); (2) заморозить v2
  до подписи ТЗ; (3) ИИ — необязательная поздняя фаза за `IDocumentRecognitionService` с дефолтным
  `ManualProvider` (система полна без GPU/Python); при ИИ — только ЛОКАЛЬНЫЙ (PaddleOCR/Tesseract +
  правила, VLM Qwen2.5-VL лишь для неоднозначностей); (4) в MVP сканы и диагноз НЕ хранить;
  (5) human-in-the-loop обязателен, авто-оценки запрещены (ФЗ-273); (6) анти-фрод «подлинности» — иллюзия, вырезать.
- **Архитектурное ядро (совет Codex):** моделировать ЖИЗНЕННЫЙ ЦИКЛ КЕЙСА справки
  `Draft → NeedsReview → Verified → (Rejected|Expired|Revoked)`; ручной ввод / импорт / загрузка / OCR —
  это разные `DraftSource`, официальный факт — только человеком подтверждённый `VerificationDecision`.
