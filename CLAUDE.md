# MedSpravki-REU

Реестр медицинских справок и допусков студентов к физкультуре; чувствительные медицинские данные.
Общие правила — [корневой CLAUDE.md](../../CLAUDE.md), устройство и ограничения — [README.md](README.md).

## Источники и границы продукта

- Перед изменением scope читать раздел README «Два ТЗ», материалы `_source/inputs/` и [docs/PROJECT-STATUS.md](docs/PROJECT-STATUS.md).
- Официальное ручное ТЗ и реализованные загрузка сканов/ИИ/личный кабинет — разные объёмы. Не выдавать реализованное за согласованное заказчиком.
- Датированные сведения о деплое и данных — история, не текущая проверка. Старый `.proeb/context-pack.md` не заменяет живые исходники; ручной паспорт сейчас отсутствует.
- `app/Directory.Build.props` — .NET 8/C# 12; `app/global.json` — SDK policy.
- `app/src/` — Domain, Application, Infrastructure, Web (ASP.NET Core/Razor Pages); `app/tests/ReuMedCertificates.UnitTests/` — доменные/application проверки.
- PostgreSQL, файловые сканы и локальный Ollama — отдельные runtime-зависимости, не необходимые для unit-тестов.

## Безопасные локальные проверки

Из корня проекта, с уже восстановленными зависимостями:

```bash
dotnet test app/tests/ReuMedCertificates.UnitTests/ReuMedCertificates.UnitTests.csproj --no-restore --verbosity minimal
dotnet build app/src/ReuMedCertificates.Web/ReuMedCertificates.Web.csproj --no-restore --verbosity minimal
```

На 2026-09-07: 14 unit-тестов PASS, Web build PASS без предупреждений и ошибок.
Это не интеграционный/E2E gate: приложение, БД, загрузка/распознавание справок и внешний доступ в этом аудите не запускались.

## Данные и эксплуатация

- Для новых тестов — только synthetic fixtures; не переносить настоящие справки, сканы или сведения студентов в логи, git и внешние модели/сервисы.
- `SeedDemoData` в Development равен false: пустой реестр не является поводом вернуть демо-данные.
- `dotnet run`, миграции, сидирование, restore и деплой могут затронуть данные; сначала установить точный контур и отдельную цель операции.
- Не путать локальную и удалённую базы. Не запускать восстановление поверх существующей БД для проверки работоспособности.
- Исторический публичный Funnel не доказывает безопасную текущую публикацию. Доступ, роли, секреты и согласованный контур требуют отдельной live-проверки без утечки медданных.
- Generated context-pack и реестр автоматически не обновлять: сначала исправить канонические документы и проверить разрешённые входные источники.
